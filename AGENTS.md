# Documentation project instructions

## About this project

- The published documentation site for **`workspace-ops`**, built on [Mintlify](https://mintlify.com).
- Pages are MDX with YAML frontmatter. Configuration lives in `docs.json`.
- **This site is a rendering of `../ARCHITECTURE.md` and its family. It is never a source.** If a page
  here disagrees with the architecture, **the page is the defect** — fix it here. If the architecture
  is genuinely wrong, say so out loud rather than editing a page to make the mismatch disappear.
- The Mintlify MCP servers are available for product knowledge: `https://mcp.mintlify.com` for
  content and settings, `https://www.mintlify.com/docs/mcp` for how to use Mintlify.

## The six tabs, and what each may contain

This is the rule that stops three audiences drifting into three inconsistent products. It is stated
for readers in `overview/how-to-read-this.mdx`; keep the two in step.

| Tab | Reader | May contain |
|---|---|---|
| **Overview** | Everyone | The problem, the core idea, the roadmap. Facts stated once |
| **For Operations** | Ops analysts | Behaviour and screens. **No** table names, JSON, routes, or module boundaries |
| **For Compliance** | Compliance, MLRO, legal | Evidence and control. Same prohibition |
| **Engineering** | Senior engineers | Contracts, schemas, ADRs, trade-offs, open questions |
| **API reference** | Implementers, publishing services | The two contracts. Every operation states its own provenance; nothing is invented to fill a gap |
| **Design** | Anyone evaluating the UI | The interface only. A screen never introduces a concept a module does not own |

**The audience tabs may restate an Overview fact; none may contradict it.** Where a mechanism matters
to a non-technical reader, link to Engineering and stop.

## Terminology

- **Event** · **envelope** · **subject** · **actor** · **workflow** · **action** · **task** · **case**
  · **delivery** — all used in the specific senses defined in `overview/glossary.mdx`. Do not
  paraphrase them.
- `observed` and `unmapped` are **opposites** and must never be described as similar.
- `no_recipient` is **amber, never green and never red**.
- A **destination** is a named row, never a URL.
- Say "the identity provider" and "the auth service" rather than naming vendors, outside the
  publishing pages.

## Style preferences

- Active voice, second person for the audience tabs.
- One idea per sentence. Sentence case for headings.
- Code formatting for identifiers, statuses, file names, routes.
- **Bold the load-bearing clause**, not the whole sentence.
- Every non-obvious claim carries the reason it is true. A rule without its failure mode gets worked
  around.

## Content boundaries

- **Never state a number that has not been measured.** Where a figure was re-measured and drifted, the
  correction goes inline and the original stays visible — a checkable number that is wrong costs more
  than one never claimed.
- **Never fill an open question with a plausible default.** Record it. A default nobody chose is worse
  than a blank, because it looks decided.
- **Never soften a limitation.** `compliance/limitations.mdx` and the *Honest limits* group exist to
  be read.
- The publishing pages are the **only** place real service names belong, and that is deliberate.

## Contracts

`contracts/` is **generated by `sync-contracts.py`** from `../contracts/`. Never edit the copy.

Run `python3 sync-contracts.py` after any upstream contract change, and
`python3 sync-contracts.py --check` to detect drift.

**Two Mintlify constraints are encoded in that script, both verified against `mint dev`, and both
fail silently rather than loudly:**

- **An external `$ref` in an OpenAPI file makes every route on the site 404.** Not the API page — the
  whole site. The script resolves the ref in the derived copy only.
- **A navigation group carrying `openapi` with no `pages` generates nothing.** So does tab-level
  `openapi` beside groups. Only group-level `openapi` **plus** an explicit `pages` list works, which
  is why the script writes those 92 entries into `docs.json`.

**Never soften the API document's provenance framing.** It is a *harvest*: only two of its 84 paths
are named above the design layer, and it emits `UNSPECIFIED` 101 times on purpose. A page that
presents it as a finished specification is a defect, because a plausible schema is indistinguishable
from a specified one six months later.

## Diagrams

Two mechanisms, and the choice is not a matter of taste.

| Use | For |
|---|---|
| **Mermaid** | Sequence diagrams, and linear flows where the layout carries no argument |
| **A component in `snippets/*.jsx`** | Structural diagrams where **the layout *is* the argument** — what sits above what, and why |

The eight-module graph is a component because a layout engine would not have chosen to put
`automation` above five peers, `directory` beneath, and `audit` across the floor — and those
positions are the claim being made.

**Rules for a diagram component:**

- Inline SVG with a `viewBox`. No external libraries — Mintlify bundles these itself.
- **The custom stylesheet must be named `custom.css` at the repository root.** Any other name is not
  picked up — verified against `mint dev`, where `styles.css` served a 500.
- Colours from `custom.css` custom properties, **always with an inline light-mode fallback**:
  `var(--wo-card, #FFFFFF)`. Without the fallback, a stylesheet that fails to load renders the
  figure black.
- Tailwind **arbitrary values are not supported** by Mintlify, so exact hexes live in `custom.css`,
  never in a `className`.
- Mono for anything that is an identifier (`create_task`, `resolveResponsible`); sans for prose.
  Same rule as the product.
- The accent is **never** a status, here as in the product.
- A real `aria-label` on the `<svg>` describing the graph in prose.
- **The figure carries the shape; a table beside it carries the enumeration.** A graph with every
  edge drawn on it is a picture nobody reads twice.

## Screens

`images/screens/*.webp` are read-only exports from `../workspace.pen`. Never hand-edit them, and never
open a `.pen` file with `Read`/`Grep`/`Write` — use the `pencil` MCP tools.

When adding a screen: export it, rename it to a readable name, and reference it with an `<img>` tag
carrying `noZoom` and a descriptive `alt`.

## Never commit

Every change is left in the working tree for the user to review and commit by hand.
